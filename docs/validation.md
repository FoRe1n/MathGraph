# Validation record

This file records checked capabilities. Build logs and `artifacts/` files provide
run-specific evidence; screenshots are captured from the actual Qt application.

Initial cloud platform: Linux x64, Python 3.12, Qt/PySide6 6.8.3.
Source launch, project round-trip, PNG/SVG/PDF exports and both theme screenshots
were exercised in offscreen Qt. Native desktop input and Windows runner results
are tracked separately. No generated UI mockup is used as QA evidence.

Final automated test counts, performance measurements and publication outcome are
recorded after validation completes. See GitHub Actions for the native Windows
build's tests, frozen startup results and artifacts. A configured workflow is not
proof of a successful Windows build or published release.

## Cloud source validation

- 79 pytest cases passed in 6.04 seconds on the initial complete run. The suite
  includes core mathematics, hostile/invalid AST input, domain holes, translated
  poles, project validation, ten-function GUI interaction, parameter independence,
  exports, mathematical previews, shortcuts and the spawned analysis worker.
- Source smoke mode passed project round-trip, PNG/SVG/PDF generation and isolated
  symbolic analysis. Actual 1400×850 light/dark and analysis captures are in
  `docs/screenshots/`; parameter, 800×580 narrow, export/settings captures are
  generated by `scripts/capture_qa.py` in `artifacts/visual-qa/`.
- A Linux onedir PyInstaller build passed resource verification and frozen smoke
  tests, including the spawned analysis process. This establishes recipe coverage
  on Linux, not native Windows compatibility.
- `scripts/benchmark.py`: 50 warm batches of 10 functions, 3,600 samples per curve,
  median 1.317 ms, p95 1.480 ms on this cloud instance. This measures numerical
  sampling only, excluding startup, Qt painting and symbolic analysis; it is not
  a Windows frame-rate claim.
- Third-party deprecation warnings from Matplotlib/pyparsing and PyQtGraph were
  observed; they did not fail tests. Qt offscreen tests do not replace physical
  mouse/display or native Windows visual QA.
